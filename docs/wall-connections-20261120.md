# 围墙连接修复（2026-11-20）

## 原因与行为

旧显示对每格墙都使用同一张横向图，未根据邻格调整方向。阻挡实际上按 48×48 整格计算，画面与碰撞不一致，看起来是无法围合的横杠。

现在根据当前建筑格子派生四方向连接，木墙、石墙、强化墙可混接；支持独立墙柱、横排、竖排、转角、T 字和十字。只有上下左右相邻格会连接，隔格或斜角不连接。门根据两侧墙确定方向，打开后门叶收至两侧，显示通道；闭门、开门沿用原来的整格碰撞规则。拆除或打毁后下一帧重算连接。连接数据不写入存档，因此原有版本 1／2／3 存档无需增加字段。

建造模式高亮附近可建格；按住定位、滑动调整、松手提交建造，取消触摸不建造。占用格、人物与怪物所在格和未探索地仍由原规则拒绝；材料按每次成功放置扣除。点“完成建造”、再次选择同一建筑或按 Esc 退出。

- `npm run typecheck`：通过。
- `scripts/check-build.mjs` 新增实际转译模块检查，验证 24 格闭合墙圈和横竖木门，防止仅 TypeScript 源码正确。
- 浏览器 `/?qa=defense` 内存样本：确认闭合矩形营地、两种门方向及混合墙材显示；按 E 开门后门洞可见；按 B 显示可建格，点击一格补墙后自动接入左侧防线，木材从 177 降至 174。
- 样本使用 PlaytestStorage，不读取或覆盖正式玩家存档。微信发布构建不会通过查询参数开放该样本。
- 最终浏览器产物复查：“完成建造”与闪现按钮无重叠，点击后格子高亮与按钮同时消失，显示“已退出放置”。微信开发工具清除文件缓存并重新打开项目后，新包启动、内容加载完成，预览成功生成约 6673 KB 的二维码包。

实际手机触控与玩家体感仍需在更新后的微信预览中验收；上述自动测试不代替真机验收。

## 构建说明

本机 Creator 命令行的资源重新导入仍可能将非脚本资源降为 `*`。失败产物由原构建保护逻辑隔离，旧可用产物保留。本次在临时项目中使用已验证的资源导入缓存，并保持未改变资源的文件时间，重新编译改动脚本；不修改用户存档，也不修改全局 Creator 配置。
