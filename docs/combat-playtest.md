# 战斗原型试玩与验收

## 当前可玩范围

当前入口已升级为生存守塔试玩版：双角色、采集制造、五槽装备、技能成长、死亡复活、昼夜四季及本地存档均已接入。移动、平 A、闪现与格挡继续沿用本页操作；完整首夜步骤见 first-night-playtest.md。早期原型的手动召怪与直接重开按钮已不再使用。

## 启动

1. 执行 `npm ci`；已安装依赖可直接进入下一步。
2. 执行 `npm run build:web` 后执行 `npm run serve`。
3. 浏览器打开 http://127.0.0.1:7457，点击“新的旅程”选择角色，或继续已有进度。手机横屏布局需在真机单独确认，浏览器窗口截图不等同真机结果。
4. 微信环境执行 `npm run build:wechat`，在微信开发者工具导入 `build/wechatgame`。项目类型应为小游戏，开发配置使用 Cocos 官方测试 ID；若账号权限或真机预览不接受该 ID，需使用用户自己的小游戏测试 AppID，不替换为小程序 AppID。

## 操作

| 动作 | 桌面 | 触屏 |
| --- | --- | --- |
| 移动 | WASD 或方向键 | 左侧摇杆 |
| 普通攻击 | J 或空格，支持按住连续挥击 | 按住平 A |
| 闪现 | K | 闪现按钮 |
| 格挡 | 按住 L | 按住格挡，松开解除 |
| 暂停 | Esc 或暂停按钮 | 暂停按钮 |

静止攻击会轻度朝向附近敌人；移动时按移动朝向攻击。闪现沿当前朝向移动，遇障碍截断。格挡只防御正面攻击，持续格挡和挡住攻击均消耗体力。按下后的短窗口可以完美格挡；重复按住不会刷新窗口。

## 已执行的规则验证

早期原型阶段 Node 规则与启动测试 32 项通过；覆盖配置错误、随机恢复、暂停叠加、大时间差、薄墙与狭路、攻击命中去重、墙后遮挡、冷却、格挡角度与体力、死亡动作禁用、敌人预警、资源失败重试和过期请求。TypeScript 检查通过。构建与实际 UI 验证以当前开发记录为准。

浏览器 1280×720 横屏实际试玩已验证移动、击杀计数、闪现冷却、格挡减伤和体力下降；微信游客模式模拟器已载入战斗版本的菜单。截图见 [战斗原型](screenshots/combat-prototype.png)。这两项不等同于 Android／iOS 手机验证。

## 用户真机与体感确认（未完成）

- 左侧摇杆持续移动时，右手同时按平 A、闪现或格挡是否顺畅；重点检查双指输入与刘海安全区域。
- 闪现距离、冷却和墙前截断是否符合预期，是否出现角色卡入树木。
- 格挡按钮是否容易按住；红色攻击预警和完美格挡反馈能否看清。
- 角色朝向、前后遮挡、字体和攻击效果在手机横屏上是否清楚。
- 切后台数十秒再返回，不能一次性补算伤害；按键或摇杆不能保持在离开前的按住状态。
- 两种操作方式的体感由用户确认后，才完成任务 2.1 与 2.6 中对应验收，不因桌面模拟通过而代勾。

## 当前实现边界

当前角色、资源、建筑及怪物使用两张原创暗色手绘图集；角色按四方向切换静态帧，尚非完整动作序列帧。怪物绕路、破墙、攻击位预约和攻城已实现。标题“暮野危机”为可修改暂名。有有效存档时可继续，无存档时该按钮不可用；资源加载失败不会清空存档。当前进度与最新测试证据以 verification-matrix.md 和 OpenSpec 任务清单为准。
